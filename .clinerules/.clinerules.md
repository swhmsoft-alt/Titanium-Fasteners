# Cline 工作规约（v3 · 正式站演进版）
> **设计原则：不写「请遵守」，只写「只有这一条路能走通」。**
> 散文规则在上下文压缩后会被优先丢弃，因此每条硬约束都对应可执行命令或机器可校验信号。

---

## 0. 开工闸门（每次任务按顺序执行）
| # | 命令 | 作用 | 失败时 |
| --- | --- | --- | --- |
| 0 | `npm run budget -- --reset` | 新原子任务开始时清零本轮账本 | — |
| 1 | `npm run grep -- "<kw>" <path>` | 唯一合法的代码检索入口（限行宽/限命中数） | 换更精准的关键词 |
| 2 | `npm run gen:products` | 涉及产品数据时，校验 `data/products/*.csv` 并生成 `.ts` | **退出码非 0，禁止进入构建** |
| 3 | `npm run budget` | 检查本会话读写与工具调用次数 | 超限立即熔断上报 |

**信息充分性检查**：开工前确认四要素齐全：**目标路由/文件落点 · 数据源 · 视觉/样式归属 · 验收标准**。任一缺失直接问用户，禁止盲目全库扫描猜测。

## 2. 写入与对话通道（防 Token 浪费铁律）

- **原子写入**：>15 行的文件**只能**通过 `write_file` / `replace_in_file` / 生成脚本一次性写入。
- **零废话交付**：禁止在对话中先草拟完整代码再落盘；禁止写完后再贴一遍源码；交付物是代码时只报文件路径 + ≤5 行变更摘要。**对话中任何代码块严格 ≤15 行。**

---

## 3. 探索与调用预算（强力止血）

| 限制项 | 阈值 | 硬性动作 |
| --- | --- | --- |
| 同一文件**手读**次数 | ≤2 | 禁止重复读取同一文件，必须利用已有上下文 |
| 单原子任务**工具调用总数** | ≤8 | 达到 8 次未完成必须停手并汇报卡点 |
| 单原子任务**勘察类调用** | ≤5 | 读文件 + grep 合计不超过 5 次 |
| `npm run grep` 命中数 | ≤20 | 命中 >20 条立刻停止，要求用户缩小范围 |
| 临时探针文件（`_*.mjs/txt/log`） | 0 | 完工收据前必须彻底删除 |

## 4. 架构与数据流边界（Astro SSG 正式站规范）

- **产品数据唯一真相源**：
  - `data/products/*.csv` 是唯一可编辑源；`src/data/products/**` 均为自动生成产物（带 BANNER 标记），**严禁手动修改生成产物**。
  - 页面与组件只能从 `@data/products` 导入数据，**严禁**在 `.astro` 或 `.tsx` 中直接读取 CSV。
  - 修改流程固定为：`改 CSV` → `跑 npm run gen:products` → `npm run build`。
- **全局与局部隔离**：
  - 单个页面/功能任务**严禁改动全局 CSS、全局布局（Layout）、页头（Header）、页脚（Footer）与主导航**。涉及全站样式重构必须单独立项。
- **URL 与内链铁律**：
  - **严禁私自捏造、修改或新增任何内部 URL 路径与路由结构**。所有内部链接必须严格对齐现有路由表或用户明确指定的路径。
- **交互岛屿（Islands）规范**：
  - 转化与表单类组件（如 `InquiryForm.tsx`）统一使用 `client:load`，禁止使用 `client:visible`（防止页面内锚点跳转 `#inquiry` 时组件未完成水合导致表单原生提交刷新丢数据）。
  - 岛屿数据在构建期通过 `props` 静态注入，不依赖运行时抓取 DOM；读取 URL hash 参数时在渲染与提交瞬间现读，不缓存旧状态。

## 5. 硬禁区（Windows / PowerShell 环境适配）

- **绝对屏蔽目录**：严禁读取或检索 `node_modules/`、`.git/`、`.astro/`、`dist/`、`build/`、`.vercel/`、`.netlify/`。
- **日志过滤读取**：严禁整篇读取构建或报错日志，必须使用 PowerShell 过滤关键信息（如 `Select-String -Path build.log -Pattern "Error|Complete!"`）。
- **命令行安全**：在 PowerShell 中执行命令时避免复杂多层转义；同一命令连续失败 **2 次** 立即停手分析原因，禁止盲目重试烧额度。
- **报错熔断**：单次 `npm run build` 报错超过 **5 条** 时立即停止自动修复，列出核心错误摘要交由用户决策。

## 6. 任务终止硬性规则
工作流：立项 → 开发实施 → 【最多两轮验证】 → 交付，任务结束
1. 验证仅检查本次修改范围内文件，禁止自动全站巡检无关代码
2. 验证轮次上限：最多2轮。修复bug后仅允许再跑一轮复核，到达上限必须交付
3. 判定验证通过标准：astro build成功，没有ERROR。非阻断WARNING只记录，不阻塞交付
4. 验证全部达标之后，输出交付总结，**立刻停止全部工具调用，任务结束，不能继续新增验证动作**
5. 严禁：反复重复执行相同build、lint命令；主动新增需求以外的检查项

## 8. 上下文熔断与会话交接

- **强制熔断**：当 Cline 界面上下文进度条达到 **10%（约 50K token）** 或单任务工具调用累计达 **8 次** 时，**立即停止一切读取与写入操作**。
- **标准交接**：在项目根目录更新 `HANDOFF.md`（仅记录三项：`Current Status` 当前进度 / `Next Step` 下一步精确动作 / `Known Pitfalls` 已踩坑点），随后在对话中输出唯一提示：**`上下文已达安全阈值，请开新会话继续`**。


## 9. 模式权限与输出硬性约束

### 1. Plan 模式（严格只读 + 禁止长输出）
- **工具白名单**：仅允许调用只读工具（`read_file`、`search_files`、`list_files`、`list_code_definition_names`）。
- **严禁写入**：绝对禁止新建、修改、删除任何文件，禁止执行任何会改变本地状态的终端命令。
- **输出限制**：在 Plan 模式下，**禁止在对话中直接输出完整代码、文件全文或大段成品内容**。仅允许输出：
  1. 只读检查的核心结论（简明扼要）。
  2. 待修改的文件路径与改动要点清单。
  3. 提示用户切换至 **Act 模式** 以开始执行。
- **强制停止**：给出方案后立即停止，等待用户手动切换模式。

### 2. Act 模式（允许写入与正式输出）
- 仅在用户明确切换到 **Act 模式** 后，才允许调用文件写入/修改工具、执行终端命令以及输出完整代码或成品内容。
